# 截帧与图片物化

浏览器路径直接截取平台播放器，不下载媒体文件。只有浏览器方法全部不可用或失败时，才使用下面明确允许的下载兜底；用户要求禁止下载时跳过该分支。

## 统一画质规则

B 站和 YouTube 的所有截帧路径均使用视频源与当前账号实际可用的最高画质档：优先最高分辨率，同分辨率有多个档位时选择平台标示的最高可用档。明确选中该档，自动档或默认档不作为完成依据；沿用可用的登录态获取账号有权使用的档位。

选档后等待实际解码画质稳定，核对生效档位和 `videoWidth` / `videoHeight`，再定位、暂停并按视频原生宽高保存。记录可用档位、选中及生效档位、解码尺寸和定位时间；地址参数、会员等级、屏幕放大或截图文件尺寸本身都不能证明已取得最高档。

最高档未能生效时记录原因并按下节重试其他可用路径。仍无法取得时明确报告画质限制，不静默降档或将低档截图标为完成。

## 选择路径

1. 桌面环境中，若已连接真实 Chrome 的浏览器扩展，优先用其控制已登录播放器。遵循当前环境浏览器工具的操作和文件导出能力；工具不能可靠保存截图时使用下一条路径。
2. 否则运行专用配置截帧脚本。
3. 上述可用浏览器方法都失败或环境没有浏览器时，执行下载兜底。

每次失败记录实际原因；不通过降低清晰度要求把未登录的干净浏览器当作已登录 Chrome。

## 浏览器扩展

读取 `book.tagged.md` 中的时间戳，打开相应播放器，定位目标秒、等待渲染并暂停后，保存纯视频区域为 `images/shot_HH_MM_SS.png`。平台地址示例：

- B 站：`https://player.bilibili.com/player.html?bvid=<id>&t=<seconds>&autoplay=1&high_quality=1&danmaku=0`
- YouTube 优先观看页：`https://www.youtube.com/watch?v=<id>&t=<seconds>s`；嵌入页 `https://www.youtube.com/embed/<id>?start=<seconds>&autoplay=1` 作为备选，直接访问可能因缺少 Referer 报错。

通过播放器画质菜单执行上述统一画质规则，并以实际播放器状态和图像检查确认定位。工具不能导出图片或读取所需证据时改用专用脚本。图片保存完成后运行：

```bash
python src/capture_frames.py <video_id> --materialize-only
```

## 专用配置脚本

```bash
python src/capture_frames.py <video_id> "<VIDEO_URL>"
```

脚本使用 `.capture-profile/`，先无头运行；页面、解码、画质、定位或截图任一阶段失败，重试备用页面，仍有缺帧再尝试有头模式。读取标签稿中的时间戳、补齐缺失帧并物化图片链接。首次初始化使用 `--setup-profile`；自定义目录使用 `--profile-dir <path>`。

专用配置与日常 Chrome 分开，需要登录才能使用最高档时先初始化登录态。B 站的流选择和 YouTube 的画质菜单选择均须满足统一画质规则；核验实际生效档位与解码尺寸。脚本以视频本身就绪为依据，不等待无关页面资源加载完成。

每次运行在视频目录写入 `capture.json`，记录各帧的目标与实际秒数、解码宽高、画质菜单选项及各阶段失败原因。抽查幻灯片和演示画面，核对时间、清晰度、遮挡。小文件只表示可疑帧；重试保持原时间点，仍不合格则报告失败。

需要替换已有截图时运行：

```bash
python src/capture_frames.py <video_id> "<VIDEO_URL>" --recapture
```

每张新图通过时间和尺寸核验后才替换旧图，旧图保存到该视频目录的 `_capture_backups/`。重截失败时保留旧图，并将本次运行报告为失败。

## 下载兜底

先检查当前登录态可获取的流，按统一画质规则下载并核验最高档源文件，保存为 `output/<video_id>/video_source.mp4`；已有文件也需核对来源档位和实际分辨率后才能复用。脚本自带的自动下载偏好 `avc1`，可能漏掉更高画质，因此本流程先准备源文件，再仅调用抽帧：

```bash
python src/extract_frames.py <video_id>
```

使用 ffmpeg 按原生尺寸抽帧，并记录源文件的档位、分辨率和各帧时间。最高档无法获取时按统一画质规则报告限制。媒体文件仅在任务未完成时供续跑使用，验证成品后按[清理约定](cleanup.md)回收。

## 完成核验

- 标签稿保持可复用，`book.md` 中每个标签替换成对应本地图片。
- 从 `capture.json` 核对所选及实际生效画质符合统一画质规则、原生尺寸和目标与实际时间；无报告的手动截图或下载抽帧需记录相同证据。
- 新写或修改标签稿后，将其复制到 `book.md` 再物化，避免两份正文漂移。
- `checkpoint ... images` 检查图片存在、PNG 文件头、时间戳与正文对应；目视质量由当前会话核验。
- 源内容确实没有需要截图的场景时，两份 Markdown 可相同，无需调用会拒绝空标签列表的截帧脚本。
