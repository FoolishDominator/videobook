# 交付前清理

生成或发布的完成条件包含清理。临时媒体、预览截图、调试素材、翻译分块、一次性脚本、重截备份和任务专用模型缓存，在成品验证通过后送入系统回收站；回收失败时保留原文件并报告，不改用永久删除或清空回收站。用户明确要求保留某项材料时优先遵循该要求。

## 视频任务

临时工作文件集中放在 `output/<video_id>/_tmp/`；下载和截帧脚本已有的临时文件位置继续由脚本维护。原始字幕保持完整，保留订正稿、译稿、修改与翻译记录、标签稿、Markdown、HTML、实际引用的图片与前端资源，以及检查点和必要的获取、截帧、发布记录。具体保留规则与引用检查由 `src/cleanup.py` 维护。

先完成当前模式的检查点与实际预览，检查清单，再执行：

```bash
python src/cleanup.py <video_id>
python src/cleanup.py <video_id> --apply
python src/pipeline.py status <video_id> --mode book
```

仅字幕任务给清理命令和状态命令加 `--mode transcript`。清理命令默认只显示候选项；`--apply` 才送入可恢复的系统回收站，且会拒绝未完成或失效的检查点、缺失的本地引用、越界路径、符号链接及链接目录。所有候选路径与子树检查通过后才调用回收后端。若清单包含用户指定保留的文件，先将其作为正式交付物链接到正文或调整保留规则，再清理。

- Windows 继续使用项目自带的 PowerShell 回收站后端。
- Linux 使用项目依赖 `Send2Trash`，按宿主桌面回收站机制处理；未安装依赖时先按 README 安装项目环境。回收站不可用、权限不足、所在文件系统不支持回收或后端未移动文件时，命令失败并报告；保留尚未回收的文件，不改用永久删除。批量回收不是事务，出错前部分文件可能已进入回收站，重试前重新预览候选项。
- 其他宿主的 `--apply` 会报不支持并保留文件，使用其可恢复的系统回收站工具，保持相同保留范围。

离线测试只使用合成临时目录、模拟回收后端与平台分支，不向真实用户回收站写入测试文件；Windows 分支在非 Windows 环境中的模拟测试不等于实际 Windows 回收站验证。

## 显式使用项目本地可恢复归档

系统回收站不可用时，经授权可显式选择本地归档。它是仓库中的恢复目录，不是系统回收站；普通 `--apply` 失败不会自动切换到此模式。仍先验证成品和原有清理清单，默认只预览：

```bash
python src/cleanup.py <video_id> --archive
python src/cleanup.py <video_id> --archive --apply
python src/cleanup.py --scratch <task_name> --archive --apply
```

成功时打印批次 ID。文件以同文件系统、不覆盖已有目标的重命名移动至 `.recycle-archive/<BATCH_ID>/files/`，清单 `manifest.json` 在移动前保存原始项目相对路径、创建时间，随后记录归档和恢复的 UTC 时间。目录已加入 `.gitignore`；不提交、不发布其中内容，不自动清空或永久删除。它与源码在同一工作区，不代替独立备份。

恢复也默认只预览，确认目标路径后再执行：

```bash
python src/cleanup.py --restore-archive <BATCH_ID>
python src/cleanup.py --restore-archive <BATCH_ID> --apply
```

恢复仅允许原项目 `output/` 内的路径；拒绝已有同名目标、符号链接、越界或重叠路径、损坏清单与缺失数据，不覆盖已有文件。归档和恢复时停止其他会写入同一任务或归档批次的进程。Linux 使用 `renameat2(RENAME_NOREPLACE)`，Windows 使用不覆盖目标的原生重命名；宿主不支持安全重命名、权限不足或跨文件系统时直接失败，不改用复制后删除。批次中途失败时保留清单、已归档的数据和未移动的原件，可用该批次的恢复命令取回已移动部分。若恢复时中断且清单与文件位置不一致，停止并检查文件，不手工改写清单来绕过检查。

旧任务缺少检查点时，先核查成品、原始字幕和旧校读记录，再按已核实的清单定向回收临时文件；不为通过清理而伪造或刷新检查点。任务中断时仅回收已经失去用途的文件，保留仍需要的下载源、ASR 进度和未合并分块，恢复并验证完成后再清理。

## 发布与仓库工作区

部署验证图和站点操作的临时文件集中放在 `output/_tmp/<task_name>/`，验证上线后运行 `python src/cleanup.py --scratch <task_name> --apply`；视频任务同时执行上述视频清理。发布提交、线上验证及清理是不同步骤，不以生成发布提交代替后两步。

发布检出、项目源码、测试、Git 历史、可用 Python 环境和浏览器登录状态属于工作环境。仓库整体瘦身时逐项核实冗余目录与调用关系；保护现有改动、活动任务和嵌套仓库，不把整个 `output/`、虚拟环境或登录配置当成缓存。废弃发布检出须先检查本地改动和未推送提交。浏览器缓存仅在专用浏览器关闭后清理，保留 cookies 与站点登录存储。

完成时确认：必要文件及其引用完整、检查点状态未因清理变差、任务临时目录已回收；仅报告实际清理的项目，遗留项说明原因。
