# 交付前清理

生成或发布的完成条件包含清理。临时媒体、预览截图、调试素材、翻译分块、一次性脚本、重截备份和任务专用模型缓存，在成品验证通过后送入系统回收站；回收失败时保留原文件并报告，不改用永久删除或清空回收站。用户明确要求保留某项材料时优先遵循该要求。

## 视频任务

临时工作文件集中放在 `output/<video_id>/_tmp/`；下载和截帧脚本已有的临时文件位置继续由脚本维护。原始字幕保持完整，保留订正稿、译稿、修改与翻译记录、标签稿、Markdown、HTML、实际引用的图片与前端资源，以及检查点和必要的获取、截帧、发布记录。具体保留规则与引用检查由 `src/cleanup.py` 维护。

先完成当前模式的检查点与实际预览，检查清单，再执行：

```bash
python src/cleanup.py <video_id>
python src/cleanup.py <video_id> --apply
python src/pipeline.py status <video_id> --mode book
```

仅字幕任务给清理命令和状态命令加 `--mode transcript`。清理命令默认只显示候选项；`--apply` 才送入 Windows 回收站，且会拒绝未完成或失效的检查点、缺失的本地引用、越界路径及链接目录。若清单包含用户指定保留的文件，先将其作为正式交付物链接到正文或调整保留规则，再清理。其他宿主使用其系统回收站工具，保持相同保留范围。

旧任务缺少检查点时，先核查成品、原始字幕和旧校读记录，再按已核实的清单定向回收临时文件；不为通过清理而伪造或刷新检查点。任务中断时仅回收已经失去用途的文件，保留仍需要的下载源、ASR 进度和未合并分块，恢复并验证完成后再清理。

## 发布与仓库工作区

部署验证图和站点操作的临时文件集中放在 `output/_tmp/<task_name>/`，验证上线后运行 `python src/cleanup.py --scratch <task_name> --apply`；视频任务同时执行上述视频清理。发布提交、线上验证及清理是不同步骤，不以生成发布提交代替后两步。

发布检出、项目源码、测试、Git 历史、可用 Python 环境和浏览器登录状态属于工作环境。仓库整体瘦身时逐项核实冗余目录与调用关系；保护现有改动、活动任务和嵌套仓库，不把整个 `output/`、虚拟环境或登录配置当成缓存。废弃发布检出须先检查本地改动和未推送提交。浏览器缓存仅在专用浏览器关闭后清理，保留 cookies 与站点登录存储。

完成时确认：必要文件及其引用完整、检查点状态未因清理变差、任务临时目录已回收；仅报告实际清理的项目，遗留项说明原因。
