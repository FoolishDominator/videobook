# 字幕翻译规范

输入为 `transcript.corrected.txt` 和 `corrections.json`。根据字幕正文确认源语言，目标语言默认 `zh`（中文）；用户明确指定其他输出语言时使用该语言。将语言决定和复核记录写入 `translation.json`。

## 逐段翻译

- 源语言与目标语言不同时，由当前 AI 会话逐段翻译，保存为 `transcript.translated.txt`。外文字幕默认在订正后译成中文，完成译稿后再编排电子书。
- 译稿每行保持订正稿的 `[MM:SS]` 时间戳、段落顺序和一行一段结构。只翻译订正后保留的段落，完整保留含义、论证、例子和限制条件；书面化重组留到电子书阶段。
- 结合上下文和订正术语表统一译法，关键术语遵循下节的原文保留规则；代码、命令、路径、URL 及必须保留的标识符维持原样。
- 逐段对照原文检查漏译、误译、数字和否定关系，将无法确认的译法记录在 `uncertain`，使用订正稿的 1 起始行号定位。
- 源语言与目标语言相同时，直接沿用 `transcript.corrected.txt`，仅写入翻译记录，无需复制字幕或创建译稿。后续是否使用译稿以记录中的语言为准，不以旧译稿是否存在为准。

## 关键术语与原文

以下规则适用于所有外文源的译稿及后续电子书，不限于英文：

- 关键专业术语、核心概念及专有方法名同时保留译名和源语言原文，采用 `中文译名（原文）`，例如 `机会成本（opportunity cost）`；用户指定其他目标语言时，将中文译名换成相应译名。普通词语无需逐词对照。
- 译稿中每个关键术语首次出现时标注原文，标注放在对应的原有字幕行内，保持段数和时间戳不变。电子书中每章首次出现该术语时也保留这一对照，同章后续可使用统一译名。
- 将关键术语的 `原文 → 译名` 对照完整写入 `translation.json.glossary`，供翻译复核和编排共用。原文以原语言订正稿及订正术语表为准，保留必要的缩写；无法确认时保留原词并记入 `uncertain`，不凭译名反推原文。

## 翻译记录

`translation.json` 使用以下结构。语言采用语言代码（例如 `en`、`zh`），确需区分地区或文字时才加后缀；`source_language` 依据实际下载的字幕，不依据视频标题。相同语言无需翻译时，两个语言字段相同，术语表及疑点可为空。

```json
{
  "source_language": "en",
  "target_language": "zh",
  "source_sha256": "订正稿文件字节的 SHA-256 值",
  "review": {"full_read": true},
  "glossary": {"checkpoint": "检查点"},
  "uncertain": []
}
```

使用以下命令获取 `source_sha256`，填入已完成对照复核的订正稿版本；订正稿变更后重新核对译文，再更新记录。

```bash
python -c "import hashlib,pathlib; print(hashlib.sha256(pathlib.Path('output/<video_id>/transcript.corrected.txt').read_bytes()).hexdigest())"
```

`full_read` 只在完整对照复核后设为 `true`；无需翻译时表示已确认全文语言符合目标语言。保留原始字幕、原语言订正稿和订正记录，译文单独保存。

## 完成标准

1. 语言记录与实际字幕及用户要求一致，订正稿版本指纹匹配。
2. 需要翻译时，译稿逐段覆盖订正稿，行数与时间戳一致；关键术语首次出现的译名、原文与术语表对应，译法统一，疑点已记录。
3. `translated` 检查点通过校验。脚本核验版本、结构和复核标记，语义准确性由当前会话对照核验。
