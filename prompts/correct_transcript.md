# 字幕订正规范

输入为原始 `transcript.json`，输出为 `transcript.corrected.txt` 与可追溯的 `corrections.json`。此阶段保留原语言和原话，电子书的书面化改写在下一阶段完成。

## 编辑边界

- 阅读标题、时长、章节和全部字幕，结合上下文建立术语表。长字幕可分块处理，记录已读区间并检查相邻块的衔接，覆盖全部段落。
- 保留有意义的字词、顺序和逐段结构；只修正明确的识别错词、漏字、截断词、口吃和无意义口癖。识别不确定时保留原文并记入待核对项。
- 删除无意义的单字、词语或短语重复，例如“我我我”→“我”、“我只要我只要”→“我只要”。整段只有杂音或口癖时可删除。
- 保留正常叠词及有意强调，例如“想想办法”“看看结果”。相邻段重复须结合上下文判断，不能用全局替换或正则自动决定语义修改。
- 每个保留段输出一行 `[MM:SS] 订正后的原话`，分钟可超过 59，起始秒取原始时间戳的整数部分。保留段顺序，原始 JSON 不变。

## 修改记录

`corrections.json` 使用以下结构，`segment` 为原始 `segments` 的 1 起始序号：

```json
{
  "source_segments": 2,
  "review": {"full_read": true, "stutter_checked": true},
  "glossary": {},
  "changes": [
    {"segment": 1, "old": "我我我来演示", "new": "我来演示", "reason": "删除口吃"},
    {"segment": 2, "old": "呃", "new": "", "reason": "整段为语气词"}
  ],
  "uncertain": []
}
```

只记录发生变化的段落，每段至多一条最终决定；`new` 为空表示删除。未修改的段落直接保留原文。待核对项记录段号、原词及疑点，术语表记录采用的规范写法。复核标记只在实际完成相应检查后设为 `true`。

机械写文件可以用脚本，但脚本只应用已经确认的清单。`checkpoint ... corrected` 会把清单重新应用到原始字幕并逐行比对修正版，检查漏段、错序、误改和无记录的删除。

## 完成标准

1. 全文已校读，所有修改和删除都有原因。
2. 对修正版额外检查残留的单字、词语、短语重复和语气词；每个候选判为修改、保留或待核对。
3. 修改记录与输出逐段一致，时间戳有序；抽查修改与有意保留的重复各若干处。
4. 未确认的术语明确留在待核对项中，不用猜测替代原文。
